**EN:** The schema is clean. The diagram speaks for itself. Two new entities, both append-only, both indexed against expected query shapes:

```
AuditLog            (10 cols, 5 idx)        FailedLoginAttempt   (4 cols, 2 idx)
├── LogID (PK)                              ├── AttemptID (PK)
├── UserID?         ← idx                   ├── Username         ┐
├── Action          ← idx                   ├── IPAddress?       │
├── EntityType?     ┐                       └── AttemptedAt      ┘ composite idx
├── EntityID?       ┘ composite idx

The audit-trail topology is intentionally decoupled from the User model so future User-schema migrations (Phase 2D Password drop) leave the audit history untouched.
